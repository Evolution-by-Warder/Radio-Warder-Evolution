# Country catalogue, test34

The receiver opens a cached country or the small bundled Slovak seed before any network request. It does not parse or migrate the old `catalogue.json` world cache. Favourites, history and custom stations keep their self-contained URLs and references in the existing state file.

The central producer remains in PiconHub's weekly catalogue workflow. `catalog/global/country-manifest.json` lists all countries, Slovakia and Czechia first and the original-source view last. Each descriptor includes a stable country ID, name, kind, count, compressed/decoded limits and SHA-256 digests. Its version is the compressed content digest. Packages live at immutable `countries/<ID>/<digest>.json.gz` paths; unchanged countries retain their path and version across publications. The manifest's revision covers its canonical content. Old package paths remain available. The existing `world-radio.receiver.json.gz` remains compatible with test33.

Selecting a country prepares only that package on a dedicated I/O worker. The worker downloads, checks digests/counts/group membership, validates station rows and atomically writes the compressed cache. The GUI receives a prepared object and activates it without whole-world validation, JSON serialization or cache writes. The original-source list is another lazy package. A newer selection cancels/supersedes the previous operation; close discards late results. Playback navigation is not changed by country loads or updates.

MENU → Update catalogue fetches the small manifest and checks versions of the selected/previously cached countries. Unchanged countries are not downloaded or revalidated. Changed visited countries are verified and cached before the manifest is atomically committed; a failure retains the old manifest and active country. Newly added, unvisited countries appear in the list but their station packages are fetched only on selection. Favourites/history are not rewritten by catalogue refreshes.

Whole-world Search is an explicit background operation using the separately cached immutable search snapshot. It is not part of startup or ordinary country updates. It returns at most 200 GUI rows and reports the total number of matches; refine a broad query. This version still downloads the full station search snapshot on first explicit use. It does not require a new search service or download all countries on ordinary updates.

Cache files live under the existing settings directory's `countries/` subdirectory, addressed by ID and content hash. Manifest input is bounded to 256 KiB, compressed packages to 8 MiB, decoded packages to 32 MiB, and station counts to 100,000. Paths must match the descriptor's fixed static layout. Truncated/corrupt/wrong-group packages and invalid manifests cannot replace an active country. Data paths remain immutable, and a subsequent request observes a fully committed manifest even if its predecessor's GUI callback was superseded.

Validation includes changed/unchanged/unvisited countries, small countries below the legacy 100-row minimum, offline startup with a large invalid legacy cache, checksum/decode bounds, cache recovery, update rollback, cancellation, latest-selection wins, GUI-thread callbacks, native player ownership and three pinned native widget fixtures. `tools/verify_country_catalogue.py` tests public packages, unchanged-update request counts, a newly selected country, cached reopening and the existing legacy endpoint. Timings from a development host are not receiver timings; the first physical receiver run remains to be checked by the owner.
